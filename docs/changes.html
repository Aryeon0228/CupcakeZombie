어디를 고쳤나요?

부분기존 상태바뀐 동작
포자 낙하화면 위부터 좌우로 흔들리며 내려오고, 닿기 직전에 감속했어요.목표에서 최대 2.5칸 위에서 내려와 가속해요. 낙하는 520 → 420ms, 좌우 흔들림은 0.18 → 0.035칸으로 줄였어요.
착지 연결낙하 포자가 접촉 후에도 남고, 착지용 포자가 따로 생성되어 잠깐 겹쳤어요.포자 한 개가 낙하부터 착지까지 담당해요. 아래 접점이 고정된 채 둥근 그림 → 눌린 그림 → 회복을 연결하고 260ms에 걸쳐 마무리해요.
접촉 효과큰 먼지 16개와 비교적 큰 잡음이 한꺼번에 났어요.작은 먼지 7개와 짧은 저음의 톡 소리로 접촉을 알려요. 포자 표시 크기도 0.405 → 0.32칸으로 줄였어요.
연쇄 효과음동시에 감염된 컵케이크마다 소리가 겹쳤어요.45ms 안의 연쇄 음은 하나로 묶고 전체 음량을 완화했어요. 압축기로 갑작스러운 피크를 줄이고, 음소거를 켜면 재생 중인 소리도 잦아들어요.
모바일 비율판 영역 폭에 좌우 여백 20px가 포함되어, CSS가 가로만 줄일 수 있었어요.실제 그림을 놓을 수 있는 폭과 높이로 계산해요. 작은 화면에서도 판 전체가 같은 비율로 들어가요.
작은 화면 하단320px 폭에서 포자 3개와 별 표시가 겹칠 수 있었어요.포자 아이콘을 조금 줄이고 별과 설명을 위아래로 배치해요.
스테이지 탐색긴 장 목록을 직접 내려야 했어요.20개 장 바로가기와 이어하기 버튼을 넣었어요. 다음 미완료 판에 테두리를 표시해요.
선택과 발사터치는 두 번, 마우스는 한 번만 눌러도 발사되어 안내와 달랐어요.둘 다 첫 입력은 미리보기, 같은 칸을 다시 누르면 발사해요. 12px 넘게 끌거나 다른 칸에서 놓으면 발사하지 않아요. Esc로 선택을 해제할 수 있어요.
동작 줄이기OS 설정을 켜도 포자 이동과 입자 효과가 계속 나왔어요.큰 이동과 입자는 생략하고 접촉 지점에 잠깐 표시해요. 판정 순서와 손님 타이밍은 같아요.

화면 비교

포자가 닿는 순간

스테이지 설계와 검토

  • 1–60과 오늘의 퍼즐 120개는 기준 버전 aa1a62f와 같은 데이터예요. 기존 진행 저장 키도 유지했어요.
  • 61·71은 각각 블루베리·시나몬롤을 배우는 직접 설계 판이에요. 나머지 138개는 장별 조건, 필수 맛, 포자 수, 성공 첫 수, 연쇄 길이로 생성한 뒤 검증했어요.
  • 7–20장에는 각 두 개의 쉬어가는 판과 세 개의 도전 판을 배치했어요. 포장은 직접 타격, 민트는 우회, 손님은 타격 순서를 생각하게 해요.
  • 새 맛을 평범한 머핀으로 바꾸거나 장애물을 없애는 비교 검사로, 해당 장의 주요 규칙이 해답에 영향을 주는지도 확인했어요. 도입·휴식 판은 별도로 다뤘어요.
  • 200개 모두 최소 포자 해법을 재생했어요. 회전·반사 중복 0개, 새 140개 모두 포자 수가 필요한 만큼 설정되어 있어요.
  • 실제 화면의 입력 처리와 연출을 포함해 200개를 자동 플레이했어요. 600별, 오류 0개였어요.
  • 규칙과 연출 판정 39,209회 비교에서 불일치 0회. 신규 맛의 방향·민트·빈칸·비닐·가장자리도 따로 검사했어요.

난도는 설계 단계의 분류예요. 사람의 풀이 시간·실패 횟수·반복감은 아직 측정하지 않았어요. iOS 실기기와 네이티브 빌드는 실행하지 않았으므로, 출시 전 화면 안전 영역·실제 효과음·진동을 확인해야 해요.
