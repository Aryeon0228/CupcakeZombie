Zombie visual size correction — 2026-10-28

Problem: matching the redesigned sprites by their width made the short, broad zombies look smaller. Butter (lid off) lost 22.8% visible height and about 30.1% alpha-weighted visible area; strawberry lost 23.0% height and 31.4% area.

Change: update only the 13 in-game zombie entries in assets/scale.json. Each uses oldK * sqrt(fresh alpha-weighted area / zombie alpha-weighted area), rounded to 3 decimals. Butter is compared with butter_open, because its lid is removed before infection. The artwork remains proportional and the existing foot anchor is preserved. Fresh/pending/mint sprites and game rules are unchanged.

Examples: butter 0.500 -> 0.598 (+19.6% linear size), strawberry 0.500 -> 0.604 (+20.8%). Across all 13 types the corrected visible area is within 0.2% of its fresh reference. Toppings can remain lower because the art has collapsed naturally.

Validation: before/after real-input clears of stage 16 at 390px and 1280px; dense 7x7 stage 40 with all infectable cells shown as zombies in an isolated visual fixture; all 13 flavors compared fresh / before / after. Same-flavor horizontal overlap is at most 0.9% of the sprite area (lemon arms); butter and strawberry have no overlap. No page errors. HTML is byte-identical outside SPRITE_K and the build stamp.

Asset reimport: preserve the per-flavor current assets/scale.json values. The versioned art-package manifests describe their original 0.5 import scale; those historical defaults do not override the current display scale. Use the current value with import-cupcake.py --k when importing revised artwork.
